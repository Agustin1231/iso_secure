¿Por qué DAST si ya hicimos SAST?

📄

SAST

Static Application Security Testing

  • ▸Lee el código fuente
  • ▸Detecta patrones peligrosos
  • ▸ruff, bandit, semgrep
  • ▸Hecho en Etapa 3
VS
⚡

DAST

Dynamic Application Security Testing

  • ▸Ataca la app corriendo
  • ▸Encuentra problemas de runtime
  • ▸OWASP ZAP, Nuclei, sqlmap
  • ▸Esta etapa

Ambos son obligatorios. Detectan cosas distintas.

Las herramientas del DAST

⚡ General

OWASP ZAP

Proxy interceptor + spider + scan activo con cientos de payloads. El "todo en uno" del DAST.

📋 Plantillas

Nuclei

Ejecuta plantillas YAML mantenidas por la comunidad. Una plantilla = una vulnerabilidad o misconfig.

💉 Inyección

sqlmap

Detecta y explota automáticamente todos los tipos de SQL injection: error-based, blind, time-based.

🔐 TLS

testssl.sh

Auditoría completa de TLS: protocolos, suites de cifrado, certificados y CVEs conocidos.

🔥 Fuzzing

ffuf

Fuzzer web ultrarápido. Descubre endpoints y parámetros ocultos con miles de peticiones.

🎫 Auth

JWT_Tool

Toolkit específico para JWT: firma débil, alg=none, kid traversal, falsificación.

Toolkit DAST seleccionadoOWASP WSTG v4.2

Estrategia: ataque en 4 capas

No se ataca todo de golpe. Se avanza por capas, cada una asumiendo más conocimiento del sistema.

CAPA 1

Reconocimiento

Sin login. Lo que un atacante anónimo ve.

  • Spider de ZAP
  • Archivos sensibles (.git, .env)
  • TLS audit
  • Versiones expuestas
CAPA 2

Autenticación

Atacar el login.

  • Enumeración de usuarios
  • Brute force
  • Credential stuffing
  • JWT (alg=none, exp)
CAPA 3

Autorizado

Con cuenta válida de bajo privilegio.

  • IDOR (cambiar IDs)
  • Cross-tenant
  • Privilege escalation
  • Tamper de parámetros
CAPA 4

Fuzzing

Peticiones masivas con datos absurdos.

  • Strings 1MB, ints negativos
  • SQL/NoSQL/SSTI
  • Unicode/emojis
  • Edge cases
Recon → Auth → Autorizado → FuzzingOWASP ASVS 4.0

Secretos & Despliegue blue-green

🔐 Gestión de secretos

Reglas estrictas

  • Nunca en el código (detect-secrets en pre-commit)
  • Nunca en logs (filtros de redacción)
  • Rotación cada 90 días
  • Mínimo privilegio por servicio
  • Vault del proveedor (Supabase, Coolify)
🚀 Blue-Green

Despliegue sin downtime

  • Coolify levanta versión "green" en paralelo
  • Healthcheck /health debe pasar
  • Swap automático de tráfico blue→green
  • Rollback si falla healthcheck
  • Cero downtime, cero riesgo

git push origin main → Coolify detecta → build → healthcheck → swap → URL viva

Continuous Deployment seguroCoolify · self-hosted
